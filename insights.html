自治体AI調達から見える5つの設計論点

データベースへ戻る
GitHub / 根拠データ

自治体のAI調達は、製品名や導入件数だけを並べても実態が見えにくい領域です。 公開された仕様書、質問回答、評価基準、選定結果をつなぐと、 「AIをどこまで使わせるか」「何を契約上の要件として固定するか」という設計判断が見えてきます。

2026年10月3日時点のRepository内のreviewed Claimをもとにした整理です。 現在の収集案件は全国の自治体を代表する標本ではなく、以下を全国傾向として一般化しません。 各論点の事実範囲はリンク先のClaimを正本とします。

01 / CONTROL BOUNDARY

「AIを使うか」ではなく、どこでAIに生成させるかを分けている

AI導入の有無だけでは、実際の統制設計を表せません。

神戸市の税務部ボイスボット調達は、音声・文脈理解にはAI技術を要求する一方、市民への回答は市が提供するFAQを基にした回答データから行い、AIによる回答生成を認めていません。 別の仕様書作成支援AI調達では、LLMが不整合を抽出して修正案を生成し、その修正案を採用するかどうかを利用者が選択することを公募時要件にしています。

ここから確認できるのは、AIの導入そのものではなく、生成を許す工程、固定データを使う工程、人間が判断する工程を分けて調達仕様に落とし込む設計が実際に存在することです。

埼玉県の2026申請・相談デジタルサポートは別の統制方法を採ります。県民向け生成AIの回答自体を許しつつ、参照した元データやページへのリンク等を見せ、根拠が見つからない場合は「不明」と回答できることを要求しています。評価表でもナレッジ表示40点、根拠なし回答制御50点を割り当てています。

税務ボイスボットのClaim ↗ 公式仕様書 ↗ 仕様書作成支援AIのClaim ↗ 公式仕様書 ↗ 埼玉県のClaim ↗ 埼玉県公式Q&A ↗

この比較は神戸市の2案件の公募時要件に限定します。自治体AI全般の標準設計を示すものではありません。

02 / PROCUREMENT SCOPE

調達仕様にない機能を「組織として使っていない」と読まない

一つの調達案件は、組織全体のAI利用環境の一部分です。

京都市の2026年度汎用生成AIサービス調達では、RAGは本調達の要件外です。 ただし資料上の理由は、京都市で導入中の他サービスによりRAGニーズを充足しているためとされています。

したがって、案件比較で RAG=false と構造化できても、それを「京都市はRAGを利用していない」「RAG需要がない」と読み替えることはできません。 調達仕様は契約スコープを示すもので、組織全体の技術構成をそのまま示すとは限りません。

03 / EFFECTIVE REQUIREMENTS

比較すべきなのは「最初の仕様書」ではなく、公募中の変更を反映した有効要件

質問回答や訂正が、実際に応募者へ適用される条件を変えることがあります。

おうみ自治体クラウドの2026生成AI共同調達では、公式質問回答により、LLM数、Deep Research、テンプレート数、自律的エージェント、認証、ネットワーク条件など複数の当初要件が変更されています。 たとえばテンプレート数は200種類以上から50種類以上へ、自律的エージェントは必須から任意へ変更されました。

仕様書だけを横断比較すると、変更前の条件を「現行要件」として残してしまいます。 このRepositoryでは元仕様と後続資料を分け、変更後の状態を effective_requirements.csv に保持しています。

Claimと変更例 ↗ 公式質問回答 ↗

これは「当初仕様が誤りだった」という意味ではなく、公募期間中に公式に適用条件が変更されたことを示します。

04 / LIFECYCLE EVIDENCE

「選定済み」「契約済み」「稼働中」は同じ状態ではない

特に共同調達では、案件単位の一つのステータスに丸めると誤読しやすくなります。

おうみ共同調達は協議会レベルの基本契約と参加自治体ごとのサービス利用契約を分けます。 群馬の共同調達も、共通選定後に各契約予定団体への再見積を行い、団体ごとに個別契約する構造です。 共通の優先交渉事業者が決まったことだけでは、全参加団体の契約締結や稼働開始を確認したことにはなりません。

さらに、現在reviewedとなっている複数案件では、公募仕様、Q&A、選定結果が公開されていても、契約協議後の最終要求文書まで公開資料だけで再構成できないケースがあります。 そのためこのRepositoryは、選定・契約・稼働を別証拠として管理し、確認できない段階を推測で埋めません。

共同調達のstageに関するClaim ↗ 群馬県公式資料 ↗ 契約最終要件の公開再構成に関するClaim ↗

「公開資料で確認できない」は「契約していない」「稼働していない」という意味ではありません。

05 / REQUIREMENT SEMANTICS

セキュリティ要件はキーワードではなく、対象と役割まで読む

同じ言葉でも、保存場所・接続先・参加資格・評価加点では意味が異なります。

大府市の2026生成AI調達では、市データを国内データセンターに保存することを求めていますが、生成AI APIの接続先所在地そのものを国内に限定してはいません。 「国内」という語だけを抽出すると、データ保存場所とAPI接続先を混同する可能性があります。

北海道の2026 RAGサービス調達では、ISO/IEC 27001認証は企画提案の加点項目ではなく、制限付一般競争入札への参加資格です。 認証名が同じでも、「持っていれば評価が上がる」のか「持っていなければ入札に参加できない」のかで調達上の意味は異なります。
