# Deep requirement extraction — 2026-09-30

## Scope

初期コーパス11案件のうち、公式仕様書・評価表を取得でき、比較可能な情報が十分にある6案件を優先して深掘りした。

対象:
- 仙台市 2026
- 大府市 2026
- 焼津市 2025
- 神戸市 2026
- 埼玉県 2026
- おうみ自治体クラウド協議会 2026

成果:
- `data/requirements.csv`
- `data/evaluation_criteria.csv`

## Evidence rule

- 仕様書・評価表の公式PDF本文で確認できた事項だけを `true` または具体値として記録した。
- PDF本文から確認できない事項は、別紙や一般的な製品仕様から推測せず `unknown` とした。
- 「望ましい」と「必須」を区別した。例: 神戸市の複数LLM・LGWAN接続は望ましい要件であり、必須要件として扱わない。
- 「LGWAN回線が存在する」ことと「LGWAN-ASPでサービス利用できること」を区別した。

## Findings

### 1. セキュリティ要件には共通核があるが、書き方はかなり違う

大府市は、入力・出力データを一般的な生成AIサービスの学習・蓄積に利用しないこと、国内データセンター保存、日本法・日本の裁判管轄、契約団体間の環境分離を明記する。

仙台市はさらに、利用可能LLMの国内リージョン、入出力内容をAI学習に利用しないこと、入出力内容をLLMサーバへ保存しないことを個別要件としている。

埼玉県も、学習利用禁止、処理後のLLMサーバ非保存、受託者の利用データアクセス制限、国内データセンター保存を要求する。

おうみ共同調達は、学習利用禁止に加え、通信暗号化、ISO/IEC 27001・27017、機密情報・個人情報入力の検知/ブロック、利用ログの保持、契約終了後の完全削除と証明書提出まで要求する。

### 2. RAGは「ある/ない」だけでは比較できない

仙台市:
- 内部事務5業務を対象
- 図表を含む文書への対応
- 参照元ファイルを直接確認
- FAQ正答率8割以上を目標
- 回答根拠がない場合の表示制御

埼玉県:
- 部局別・事務別のナレッジ領域
- 根拠文書表示
- 根拠がない場合は「不明」と回答
- 50MB以上のファイル
- PDF/Office/画像等
- Web検索と特定Webサイト参照
- Box連携

おうみ:
- 団体ごとに100GB以上
- PDF/PPTX/DOCX/XLSX/CSV/TXT
- 参照ソース確認
- LLM/RAG/Web検索を組み合わせたテンプレート

神戸市:
- RAGを仕様書作成・文書レビューに直接組み込み
- 文書間/文書内整合性チェック
- 修正案生成
- ベース文書選択
- 仕様書案生成・自然文修正
- 1TB以上のファイル容量

したがって、今後は `rag=true` だけではなく、RAG用途・データ容量・ファイル形式・根拠表示・管理方式を別々に保持する必要がある。

### 3. 2026年度案件では、単一LLM調達から「複数モデル選択」へ進んでいる例がある

埼玉県は複数LLMを利用できることを要求し、提案者に種類・バージョン・単価・特徴の提示を求める。

おうみ共同調達はさらに具体的で、無償・有償のモデル群を仕様書内で列挙し、国内/海外リージョンを確認しながら利用設定できること、新モデルへ適切に追随することを要求している。

一方、仙台市は「ChatGPT-4.1 mini同等以上」という性能下限を置き、国内リージョンを要求する方式である。

### 4. Deep Research / AI agentまで調達要件に入る案件が出ている

おうみ共同調達は、Deep Research、自律的エージェント、Webページ閲覧、画像生成等の外部ツール自動選択、業務別プリセットエージェントを仕様書の機能要件に含める。

埼玉県もAIエージェントを仕様書に明記し、提案評価で20点を配点している。

これは「自治体生成AI調達 = 安全なチャットUI」という段階から、検索・RAG・エージェントを含む業務基盤へ対象が広がっていることを示す。ただし、今回の6案件だけから全国的な傾向と断定はしない。

### 5. 評価基準は、自治体が何を重視しているかを直接示す

仙台市（110点）では、画面デザイン・操作性が40点、生成AI導入実績が15点、基本機能が15点。RAGの回答精度、根拠表示、テンプレートは面接審査で実際の操作を評価する。

埼玉県（410点）では、ハルシネーション防止50点、参照ナレッジ表示40点、回答精度向上40点、翌年度ランニングコスト40点など、回答品質とスケール時の費用が高配点。

神戸市（100点）では、提案内容65点、業務遂行能力15点、価格10点、所在地10点。機能要件への対応と構築方法が各20点。

「仕様書」だけでなく「評価表」を収集する価値が高い。

## Data model changes suggested by evidence

次の詳細抽出では、少なくとも以下を独立列または子テーブルとして扱う。

- domestic / overseas region policy
- RAG storage capacity
- RAG accepted file types
- source citation / grounding display
- hallucination fallback behavior
- Web search
- designated-site search
- Deep Research
- AI agent
- Box / external storage integration
- training-data prohibition
- LLM server retention prohibition
- log retention period
- end-of-contract deletion
- LGWAN / LGWAN-ASP
- user count / concurrent count
- usage cap
- response target / SLA
- evaluation criterion and points

## Important limitations

- 大府市の詳細機能はExcelの「業務要件一覧（1次審査表）」に委ねられているため、現時点ではRAGや複数LLM等を仕様書だけから推定していない。
- 焼津市も詳細機能はExcel「要求機能一覧」に記載されており、今回の抽出はPDF仕様書で確認できた範囲に限定した。
- 神戸市のAzure OpenAI Service要件は「神戸市におけるAIの活用等に関する条例」第7条に該当する場合という条件付き。
- おうみ仕様書で列挙されたモデル名は令和8年2月1日時点と明記され、同等以上の代替モデルを許容する。
